# Tests and files that cannot run where Pi's profile is absent (RS3SYNC, OL12 D6, RS3CI).
#
# The clone at ~/projects/muster carries the packages, not Pi's profile: there is no
# extensions/, scripts/, memory/ or health/ beside the packages, no profile project
# register and no shipped pool file. A test that reads one of those fails here for that
# reason and passes only where the packages live inside the profile.
#
# Format, one entry per line, tab-separated:
#
#   <path relative to this file's parent>  <test name, as a regular expression>  <reason>
#
# The name matches the whole test name or its last segment after "> ", so an entry
# covers exactly one test and never a whole file. An entry is admissible only when the
# test fails here for the reason it states; a test that passes in this clone must not be
# listed. `./test.sh` passes each expression to node's own runner as
# `--test-skip-pattern`; the guarded runner this machine uses takes files only and
# inherits no environment (systemd-run starts the unit with its own), so a guarded local
# run still executes the listed tests and stays red on them. CI, which has no guard,
# skips them and is the run this file exists for.
#
# Every entry below was measured, not assumed (RS3CI). A run with `env -i`, a fresh empty
# HOME, a PATH holding only node and the system binaries, no guard and no Pi profile named
# exactly these tests as failing or as hanging, and each reason names the profile artifact
# that test reached for: the shipped `provider-pool.json`, the `extensions/muster` tree with
# its launchers and hook bundles, the `scripts/` a lane or a watcher runs, Pi's model
# registry and project register, and the `packages/` tree. The first CI run on this
# repository timed out for want of this list; a test that passes in that run is not listed.
#
# The list was re-measured as a whole after the second sync (RS4SYNC): every test file run
# alone on the same bare runner, the five file entries named again, and one entry added for a
# test that reads a file at the profile root, above the packages tree.
#
# A pattern field of `-` means the file itself. Such a file reads the profile while it
# imports, so it throws before any test exists and no test name can skip it; the run
# leaves the file out instead. Nothing is hidden by that: the file reports no result for
# any of its tests either way.
#
# Path/tab-regex/tab-reason follows.
